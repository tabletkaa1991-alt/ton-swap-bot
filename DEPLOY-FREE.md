# Переезд на бесплатный сервер: что делать

## Сначала — почему бот «умер»

Из `.run` логов видно две независимые причины, обе устранены в коде:

1. **`No matching tunnelmole domain`** — бесплатный адрес tunnelmole живёт ограниченное время.
   Когда он умирает, ссылка на мини-приложение перестаёт работать, а watchdog перезапускает
   всё с новым адресом. Это не ваш сервер и не ваш код — это сам tunnelmole.
   → Локальный запуск исправлен: сначала бот занимает порт 8080, потом поднимается туннель
   (tunnelmole, при неудаче cloudflared), адрес переписывается в `.env`, бот перезапускается
   и ставит кнопку меню. Правильное решение — переезд на сервер, где туннель не нужен вообще.
2. **`Cannot connect to host api.telegram.org ... Превышен таймаут семафора`** — провайдер
   периодически режет Telegram API. На бесплатном сервере за границей этой проблемы нет,
   локально нужен VPN или `PROXY_URL` в `.env`.

Заодно исправлено то, что мешало серверному запуску:

| Было | Стало |
|---|---|
| Статика на node :8080, отчёты на python :8090, `/api` проксировал node | **Один процесс** `bot/web.py` отдаёт статику, `/api/*`, `/api/health` и бота |
| Caddy на VPS отдавал только статику → `/api/report` и `/api/health` давали 404 | Caddy проксирует всё на бота |
| `Dockerfile` копировал только `bot/` — без `webapp/` мини-приложение не работало | Копируются `bot/` и `webapp/` |
| Адрес мини-приложения надо было руками прописывать в `.env` и манифесте | Адрес берётся из `RENDER_EXTERNAL_URL`/`KOYEB_PUBLIC_DOMAIN`, манифест отдаётся на лету |
| Меню-кнопка ставилось `node tools/set-menu-button.mjs` | Бот ставит её сам при старте |
| Бот умел только polling | Плюс режим вебхука (`WEBHOOK_URL`), если хостинг будит контейнер запросом |

Проверка после изменений: `python -m unittest discover -s tests -v` — все тесты зелёные.

## Вариант A: Render Free (без карты)

### 1. Положить проект в GitHub

Нужен бесплатный аккаунт GitHub. **Git на этом компьютере не установлен**, поэтому есть
два пути — оба рабочие:

**Путь без установки Git (проще).** В папке проекта уже лежит готовый архив
`ton-swap-bot-deploy.zip` — в нём только нужные файлы, без `.env` и без секретов.

1. github.com → **New repository** → имя `ton-swap-bot`, **Private**, Create.
2. На странице пустого репозитория → **uploading an existing file** →
   перетащите туда **содержимое** архива (папки `bot/`, `webapp/`, `deploy/`, `tools/`,
   `tests/` и файлы `render.yaml`, `requirements.txt`, `.dockerignore`, `README.md`, …),
   затем **Commit changes**.
3. Проверьте, что в репозитории **нет** файла `.env` — там токен.

**Путь с Git.** Установите [Git for Windows](https://git-scm.com/download/win), затем:

```bash
git init && git add . && git commit -m "free deploy"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ton-swap-bot.git
git push -u origin main
```

`.env` в git не попадёт (он в `.gitignore`) — это правильно, секреты вводятся в панели Render.

### 2. Создать сервис в Render

1. https://render.com → **Get Started** → вход через GitHub.
2. **New → Blueprint** → выбрать репозиторий `ton-swap-bot`.
3. Render прочитает `render.yaml` и спросит значения переменных:
   - `BOT_TOKEN` — токен из @BotFather;
   - `TONAPI_KEY` — ключ из tonconsole.
4. **Apply** → подождать 3–5 минут (сборка Docker-образа).

`render.yaml` уже задаёт: free-план, регион Frankfurt, Dockerfile `deploy/Dockerfile`,
health-check `/api/health`, лимиты, комиссию, `SERVICE_WALLET`.

### 3. Проверить

Адрес будет вида `https://ton-swap-bot-xxxx.onrender.com` (Render покажет его в панели).
Бот сам возьмёт его из `RENDER_EXTERNAL_URL` — руками в `.env` ничего писать не нужно.

Откройте по очереди:

- `https://АДРЕС/api/health` → `{"ok": true, "bot": "fastobmennik_bot"}`
- `https://АДРЕС/api/config` → юзернейм бота и лимиты
- `https://АДРЕС/tonconnect-manifest.json` → `url` равен вашему адресу
- `https://АДРЕС/` → мини-приложение, кнопка подключения кошелька
- в Telegram: `/start` у бота → кнопка «Открыть обменник» и курс

### 4. Не давать засыпать (важно)

Free-сервис Render засыпает после ~15 минут без входящих запросов; после сна первый
запрос ждёт ~минуту. Разбудить его может любой пинг `/api/health`:

1. https://cron-job.org (бесплатно, без карты) → Create cronjob:
   - URL: `https://АДРЕС/api/health`
   - каждые 10 минут (при 31 дне это 744 часа — влезает в лимит 750).
2. Или UptimeRobot: HTTP-монитор того же URL с интервалом 5–10 минут.

Пока пинг работает, бот отвечает круглосуточно. Если пинг остановить — бот будет
просыпаться только при заходе в мини-приложение, сообщения в чате могут задержаться.

## Вариант B: Koyeb Free (без карты)

1. https://app.koyeb.com → регистрация через GitHub.
2. **Create Service → GitHub** → репозиторий → builder **Dockerfile**,
   путь `deploy/Dockerfile`, порт **8080** (или `PORT` из окружения), инстанс **Free**.
3. Environment variables: `BOT_TOKEN`, `TONAPI_KEY`, `NETWORK=mainnet`, `FEE_PERCENT=2.5`,
   `MIN_USD=1`, `MAX_USD=10`, `SERVICE_WALLET=...`.
4. Deploy. Koyeb выдаст `https://имя-приложения.koyeb.app` — бот определит адрес
   через `KOYEB_PUBLIC_DOMAIN` сам.
5. Free-инстанс засыпает после часа без запросов — поставьте пинг `/api/health`
   каждые 20 минут (cron-job.org/UptimeRobot).

## Вариант C: Oracle Cloud Always Free

Полная инструкция в `DEPLOY-ORACLE.md`, но теперь короче: после `git clone`/`scp` проекта

```bash
cd /opt/ton-swap-bot
DOMAIN=ваш-домен bash deploy/install.sh
```

`install.sh` сам поставит Docker, откроет 80/443, соберёт единый контейнер, поднимет Caddy
с Let's Encrypt и проверит `/api/health`. Нужна только A-запись домена на IP сервера.

## Вариант D: Cloudflare Workers (без карты и без сна)

Плюсы: не засыпает, нет контейнера, бесплатно навсегда (100 тыс. запросов/день).
Минусы: Python-код не переносится 1:1 — бот переписывается на TypeScript/grammY,
вместо polling — вебхук (который уже поддержан в текущем коде как `WEBHOOK_URL`).
Логика (`/start`, `/rate`, `/fee`, `/report` с проверкой initData, уведомление с галочкой)
переносится один в один; статика мини-приложения — Cloudflare Static Assets.
Работы ~1–2 часа, аккаунт Cloudflare бесплатный, карта не нужна.

⚠️ **Главное ограничение для РФ.** С июня 2025 российские провайдеры системно тротлят
сайты за Cloudflare — [Cloudflare подтверждает](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/service-disruption/)
ограничение примерно 16 КБ на соединение, из-за чего сайты «недоступны или непригодны»
для посетителей из России. Сам бот будет работать (Telegram стучится в Worker со своих
серверов, не из РФ), но **мини-приложение открывается браузером пользователя** — у
российской аудитории оно может не загрузиться. Поэтому для РФ Render/Koyeb надёжнее,
а Workers имеет смысл, если аудитория не из России или есть свой домен не на Cloudflare.

## Чек-лист после переезда

- [ ] `https://АДРЕС/api/health` → 200 `{"ok": true}`
- [ ] `/tonconnect-manifest.json` содержит ваш новый адрес, а не `example.com`
- [ ] `/start` в боте отвечает, кнопка меню «Обмен» ведёт в мини-приложение
- [ ] кошелёк подключается, котировка приходит
- [ ] тестовый обмен: в чат приходит одно сообщение с галочкой и деталями
- [ ] пинг `/api/health` настроен (если Render/Koyeb)
- [ ] локальная автозагрузка **отключена**: удалить `start-hidden.vbs` из
      `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` — иначе бот будет
      одновременно работать на ноутбуке и на сервере (конфликт `getUpdates`)
- [ ] на ноутбуке бот остановлен: `.\tools\stop-stack.ps1`

## Секреты (обязательно к ротации)

Токен уже уходил в переписку и в этот архив, поэтому:

1. @BotFather → `/mybots` → бот → **API Token** → `/revoke` → новый токен.
2. tonconsole → API keys → создать новый ключ, старый удалить.
3. Новые значения вписать в панели хостинга (Render → Environment) и локальный `.env`.
4. Архив `дикпик.zip` и `.env.txt` из него удалить или хранить в защищённом месте —
   там лежат токен и ключ в открытом виде.

## Обновление кода после переезда

```bash
git add -A && git commit -m "..." && git push
```

Render/Koyeb пересоберут сервис сами (1–3 минуты). Локальный режим по-прежнему живёт
через `.\start.ps1` — он нужен только для отладки.
